# 喵喵叫的可爱助手 · PIXELFORGE

> **一个本地运行的 AI 游戏素材生成台**，外加它自己正在用的**模型实验场**。
>
> 一句话定位：把一张角色参考图，用本地模型 + 确定性后处理，规整成可以真正放进游戏引擎的像素精灵、透明底、四视图、八方向行走帧；并持续攻克「自动扣出语义部件 → 套现成骨骼 → 导出可动 GIF」这条最难的路。

- **项目名** `pixelforge`，**界面名**「喵喵叫的可爱助手」（Meowcute）。
- 全部离线、本机推理，不依赖任何云端 API。
- 既是一个可用的生产工具（无限画布工作流编辑器），也是一条还在迭代的研究链路。

---

## 这个项目在解决什么

做像素游戏素材，最大的痛不是「出一张好看的图」，而是「出一张**结构稳定、可拆解、可动**的图」。

- 模型天生擅长「画一张好看的图」，但不擅长「头/臂/躯干/腿是分开的、可被分别替换和摆动的」。
- 于是有了两条互相支撑的战线：
  1. **生产面**：用提示词契约 + FFT 网格对齐 + 共享色板，把模型输出规整成干净的像素精灵；用编辑底座做四视图/八方向推导，产出可摆进引擎的精灵表与行走帧。
  2. **研究面（当前重心）**：一张人物参考图 → **语义部件**（头/双臂/躯干/双腿各自独立）→ 套现成骨骼行走骨架 → 导出 GIF。关键词是「扣部件」——这也是本项目反复受挫、反复重试、目前最看重的那一步。

---

## 它能做什么：工作流模板

App 以「无限画布」组织：每个项目是一块画布，生成卡和结果卡摆开，随时回来继续。内置 7 个工作流模板：

| 模板 | 输入 → 产出 | 用途 |
|---|---|---|
| **像素精灵 · 文字生图** | 描述 → 像素风角色 | 文生图 + FFT 网格对齐 + 调色板量化 + 抠底落卡 |
| **像素精修 · 图片转像素** | 任意图 → 像素 PNG | 把现成图规整成原生像素（网格对齐 + 色板） |
| **扣除背景 · 图片转透明底** | 任意图 → 透明 PNG | u2net 语义分割 → GrabCut → 颜色键，硬边 alpha |
| **逐帧动作精灵表** | 图 / 序列 → 横排精灵表 | 动作帧规整成可直接用的精灵表 |
| **角色四视图** | 正视图 → 侧/背/右视图 | 编辑底座指令接力转朝向，四视图拼板对齐 |
| **八方向行走** | 一张角色图 → 四视图 → 八方向行走视频 → 精灵表 → 可操控预览 | 全链路：立绘 → Wan 行走视频 → 序列帧 → 精灵整图 |
| **场景语义分层** | 场景图 → 分层资产 | 场景按语义拆层，便于引擎里分别处理 |

每个模板都定义好「输入 → 几步流程 → 产出」四步结构，子步骤可在画布上展开、连线、复用。

```

│  └─ app/
│     ├─ main.py           全部 HTTP 端点（生成/编辑/三视图/行走/序列帧/精灵表…）
│     ├─ config.py         运行时配置、模型扫描
│     ├─ templates.py      7 个工作流模板定义
│     ├─ custom_templates.py  用户自定义模板持久化
│     ├─ projects.py       项目 CRUD + 画布状态白名单清洗
│     ├─ storage.py        项目目录资产落盘、文件夹清单
│     ├─ styles.py         画风 / 背景预设 / 像素契约 / 提示词拼装
│     ├─ prompt_examples.py 内置示例（可增删改、软删除）
│     ├─ doctor.py         环境体检
│     ├─ progress.py       任务进度与取消（SSE）
│     ├─ providers/        diffusers 本地底座（Z-Image / Qwen 家族）
│     └─ pipelines/        perfect_pixel · palette · refine · matte ·
│                          sequence · spritesheet · threeview · walkvideo
├─ frontend/              React 18 + TypeScript + Vite（模板/项目/画布/设置四页）
├─ models/                本地模型权重（由使用方配置，详见文末）
├─ tools/                 实验脚本（扣部件 / 行走骨架 / 底座选型实测）
├─ data/projects/         项目数据（画布状态 + 原图 + 精修成品）
└─ docs/                  调研与方案文档
```

- **后端**：FastAPI；推理走 `diffusers` 本地底座，家族互斥换出（不同时驻留）以省显存。
- **前端**：React 18 + TypeScript + Vite，无限画布交互（缩放/平移/拖节点/连线/删除）。
- **模型层是两条腿**：
  - 生产面：文生图默认 **Z-Image-Turbo**；编辑/四视图/八方向推导当前底座 **Qwen-Image-2.1**（原生 RGBA 透明，比上一代 edit-2511 更忠实、更省显存）；行走视频用 **Wan2.2-TI2V-5B**。
  - 研究面（`tools/`）：`exp_exploded_parts.py`（扣部件爆炸图）+ `rigwalk_ghibli.py`（套骨骼行走），以及 see-through 候选方案。
- **后处理纯 numpy/PIL**：FFT 网格对齐、共享调色板、抠图都不碰模型，几秒出结果，无 GPU 也能测。

## 核心管线原理

### 像素风为什么能干净

光写一句 "pixel art" 出不了像素图——模型只会给你一张「看起来像像素」的模糊图。这里拆成三道互相兜底的关卡：

1. **提示词契约**（生成侧）：把网格尺寸、每格单色、限定色板、无抗锯齿、硬轮廓写进提示词，先让模型往网格上画。风格词放最前——Z-Image 的编码器是因果结构，尾部 token 权重最弱。
2. **FFT 网格对齐**（后处理）：FFT 找出画面里真实的像素块大小 → Sobel 梯度峰吸附网格线 → 每格多数表决采样。块大小是量出来的，不靠猜。
3. **共享调色板**（后处理）：频次加权最远点采样压到 16 色内。按出现频次加权（而非面积占比，否则背景白占满色位），用感知距离（2/4/3）挑色。

### 视图推导（四视图 / 八方向）

编辑底座按「给一张角色图 + 一句中文指令，只改朝向、其余以参考图为准」接力推导：正视图为锚，侧/背/右视图由指令接力生成；八方向以四视图为锚点做最近锚点接力旋转（右半边 3 个方向用整段帧镜像，省一半视频时间）。**忠实度（该动的动、不该动的别动）比好看更重要**——这是选型时一票否决的硬标准。

## 当前研究方向：自动扣部件 → 行走 GIF

> 这是项目现在最看重的实验链路，也是反复栽跟头的地方。

**目标**：一张人物参考图 → 语义部件（头/双臂/躯干/双腿各自独立）→ 套现成骨骼行走骨架 → GIF。

**已验证可用路线（edit-2511 爆炸图）**，`tools/exp_exploded_parts.py --ghibli --enhance --v3 --mirror` + `tools/rigwalk_ghibli.py <部件目录>`：

1. 提示词把布局钉成网格（头/双臂/躯干/双腿各行），**v3 关键：强制头与躯干断开留白**，负向禁「头身一体」。
2. 分割掩码 = `luma<190 | chroma>40`（暗描边或高饱和），连通域 + `binary_fill_holes`，**alpha 用掩码**（不能按白色阈值抠底，白身体会被抠穿）。
3. **面积必须在 fill_holes 之后算**（浅色填充件如米白裙，填充前算只剩描边，会漏判为躯干）。
4. 角色指派：头带校验（质心在顶部 30% 且非最大块）+ 头身一体回退；躯干=剩余最大块；腿=最下两件；臂=其余最大两件；左右相对躯干中线。
5. 缺对称件用对侧 `FLIP_LEFT_RIGHT` 镜像补。
6. 套正弦行走骨架（8 帧 140ms）导出 GIF。

**适用边界**：像素小人（黑描边界限清晰）100% 成功；手绘复杂角色 v3 提示词下可用，但偶发缺件/风格漂移，需 `--resplit` 快速回归（不占 GPU）。

**更根本的候选方案**：see-through（Shitagaki Lab, SIGGRAPH 2026）——单图 → 23 个语义透明图层（已 inpaint 遮挡），三模型 LayerDiff 3D + Marigold + SAM。尚在等权重可下载后与爆炸图路线同角色对比。

**已证伪、勿重试**：Qwen-Image-Layered 拆出的是「合成层」非部件语义；按「白色→透明」颜色阈值抠图会抠穿白身体；Lightning 蒸馏 LoRA 在本项目 fp8+offload 栈上既慢又掉画质（见 `docs/模型选型调研-2026-10-21.md`）。

## 快速开始

```bash
# Windows
start.bat

# macOS / Linux / Git Bash
./start.sh
```

首次自动装核心依赖并构建前端，然后打开 `http://127.0.0.1:8788`。

**没装 GPU 也能跑**：项目管理、提示词示例库、画风浏览、像素精修（纯 numpy/PIL）都可用，只有「生成 / 编辑 / 行走视频」需要 GPU 推理依赖：

```bash
start.bat --gpu      # 或 ./start.sh --gpu
```

开发模式（前端热更新）：`start.bat --dev`（后端 8788 + Vite 5173）。其它参数：`--setup` 只装依赖、`--no-open` 不自动开浏览器、`--help` 看用法。

### 启动脚本的硬约束（Windows）

`start.bat` 必须保持 **CRLF 换行 + GBK（cp936）编码**，都是被 cmd.exe 逼的：

- **只给 LF 换行**：cmd 按 CRLF 切分语句，会把相邻两行粘成一条命令。
- **存成 UTF-8**：cmd 在行内按字节偏移解析，中文会把紧随其后的命令吃掉，报 `'xxx' 不是内部或外部命令`。编辑器的「另存为 UTF-8」是这个脚本的头号杀手。

### 找不到 / 选错 Python

脚本按此顺序挑解释器：`PYTHON` 环境变量 → `.venv/` → `python` → `py -3.13` → `-3.12` → `-3.11`。**越新越容易装不上**：

- `where python` 指向 `...\WindowsApps\python.exe` 是微软商店占位程序（退出码 9009），脚本用 `-c "import sys"` 实跑跳过它。彻底解决：设置 → 应用 → 高级应用设置 → 应用执行别名，关掉 `python.exe` / `python3.exe`。
- 系统 Python 太新（3.14+）会退化成源码编译，需 MSVC。用 3.12 最省事。

强制指定解释器：`set PYTHON=C:\Python312\python.exe && start.bat`。

## 项目文件夹：输入和产出都在里面

```
data/projects/<项目 id>/
  README.txt        自动生成的说明，翻目录时不用猜
  project.json      画布状态：生成卡描述/参考图引用/尺寸/张数/背景/画风/像素参数，
                    结果卡图片引用与元数据，以及画布缩放平移位置
  refs/             输入：上传的参考图（ref-*.png）
  images/           产出：模型原图（out-*.png）+ 像素精修成品（px-*.png）
```

文件名带时间戳和序号，例如 `out-20261021-093012-2-a1b2.png` = 那次生成的第二张原图。**整个文件夹拷走就能换机器继续**，路径无关。画布顶栏「文件夹」按钮可看清单并在文件管理器中打开。

## 图标

标签页那只猫不是手绘的，是本项目自己的管线生成的（拿产品当第一个用户）：

```bash
python tools/gen_icon.py          # 模型按像素契约出 4 张候选 → 精修到 32×32 → tools/icon_candidates.png
python tools/gen_icon.py --pick 1 # 选第 1 张，写成 favicon.ico / favicon-32.png / favicon-192.png
```

流程：Z-Image 按「32×32 网格 + 12 色 + 硬边」契约出图 → FFT 网格对齐精修 → 泛洪抠掉中灰背景。16px 档不走最近邻硬缩（会打断轮廓），改 2×2 块多数表决降采样。

## 技术栈与版本约束

FastAPI + React 18 + TypeScript + Vite。GPU 推理依赖版本互相咬得很紧，已验证可用组合：

```
torch 2.6.0+cu124 · torchvision 0.21.0 · diffusers 0.38.0
transformers 4.57.6 (<5，5.x 会破 diffusers 的 import)
torchao 0.16.0 · accelerate 1.15.0
```

> 注：Qwen-Image-2.1 底座要求 `diffusers>=0.41` 与 `transformers>=5.17`，与旧文档的 0.38/4.57 并存时需按实际加载的底座切换环境。显存策略：家族互斥换出、transformer fp8 权重量化并落盘缓存、`enable_model_cpu_offload`，用完即放。

## 模型权重

本地模型权重由使用方自己配置：填绝对路径，或建目录联接 `mklink /J <项目>\models D:\code\pixelforge\models`。代码按角色引用以下底座（权重需自备）：

| 底座 | 角色 | 备注 |
|---|---|---|
| **Z-Image-Turbo** | 文生图（中文原生） | 默认生图底座 |
| **Qwen-Image-2.1** | 指令式编辑 / 四视图 / 八方向推导 | 原生 RGBA 透明、更忠实、更省显存，当前编辑默认底座 |
| Qwen-Image-Edit-2511 | 上一代编辑底座（fp8） | 迁移对照基线 |
| Wan2.2-TI2V-5B | 行走视频生成 | fp8 量化 |
| see-through（外部） | 单图→23 语义透明图层 | 候选方案，权重待下载 |

当前 `models/` 目录已就位的权重：`qwen-image-2.1`、`wan2.2-ti2v-5b`。
